## 4) «free i» — وكيل ينفّذ الأوامر (بُني في 2026-11-08)
**ما هو:** خيار في قائمة النماذج للمالك فقط. حين يُختار تُعامَل رسائله العادية كـ**أوامر تُنفَّذ** (لا مجرد أسئلة). هو **علامة على المحادثة (`freei`) وليس نموذجًا** من التطبيق، فلا يمرّ إلى أدوات نوفا ولا استوديوهاته (`chooseModel` في `src/lib/coderModels.ts`).
**المسار:** رسالة المالك ← `src/lib/coderSections.ts` (قبل نوفا) ← `src/lib/aiAgentBridge.ts` تفتح issue (وسم `from-telegram`) ← `.github/workflows/ai-agent.yml` ← **`ai-agent/agent_loop.py`**: حلقة أدوات يقودها نموذج مجاني، كل خطوة JSON واحد، والكود ينفّذ ويعيد النتيجة حتى `final` ← تعليق على الـissue ← `ai-telegram-bridge.yml` (`relay`) يرسله إلى المحادثة. أي issue من مالك/عضو/متعاون تُنفَّذ بالطريقة نفسها من GitHub مباشرة. `AI_AGENT_LOOP=0` يعيد الوضع القديم (تعليق تحليل فقط).
**الأدوات:** `list_files, read_file, search, write_file, edit_file, run` (قائمة سماح: اختبارات ومحلل وgit للقراءة)، `open_pr, open_pull, merge_pr, run_workflow, workflow_runs, final`. اختُبرت حيًّا: قراءة وإجابة (2-4 خطوات)، وتعديل ملف وفتح PR (سطران مضافان وصفر محذوف).
**حدود في الكود (لا يتجاوزها النموذج):** لا كتابة في `athar/` و`cloudflare/` و`deploy/oracle/` و`.github/workflows/` ولا ملفات أسرار/تعليمات ولا `ai-agent/ai_agent.py`/`agent_loop.py`؛ يعدّل فقط على فرع `ai/issue-N-…` ويصل للفرع الافتراضي بـPR؛ `merge_pr` يرفض #184 و#505 و#237 وأي PR يمس مسارًا محميًا وأي قاعدة غير الافتراضي أو `main`؛ تشغيل workflows لعائلات deploy/sham/nova/computer/studio فقط؛ 30 خطوة و40 دقيقة، وعند بلوغ الحد يكتب خلاصة. **لم يُجرَّب حيًّا بعد:** `merge_pr` و`run_workflow` (الاختبارات الآلية فقط). PR التي يفتحها بـ`GITHUB_TOKEN` لا يبدأ لها CI؛ ينفّذ الاختبارات المحلية بـ`run` أولًا.
**النماذج:** الافتراضي `AGENT_MODELS` في `ai-agent/ai_agent.py`: `groq/auto` (قائمة Groq الحيّة تُجلب كل تشغيل، سرّ `GROQ_API_KEY` موجود في GitHub) ثم نماذج OpenRouter المجانية التي تدعم الأدوات. **حصة OpenRouter المجانية نحو 50 طلبًا يوميًا وكل خطوة طلب: نفدت في أول اختبار (HTTP 429)**؛ لذلك Groq أولًا. تقبل `AI_MODEL` (متغير مستودع) قائمة بمعرّفات OpenRouter أو `groq/<id>`. القارئ يفهم صيغ الأدوات المختلفة (JSON وQwen XML وLiquid).

- **مستواه (قُرئ 2026-11-08):** خسارة المقياس المحجوز في آخر دمج: **نص 4.59 ومحادثة 2.03 ووسائط 7.24** (الأقل أفضل). الاستوديو يخدم `final_merged.pt` عند الخطوة **61,555** (قديمة). نقطة المحادثة عند الخطوة 85,917 **رُفض دمجها** (لم تحسّن كل المهارات معًا: +0.0%/+0.7%/-0.0%): البوابة تعمل كما صُمّمت، والتدريب يبدو في هضبة. ردود الاستوديو على أسئلة بسيطة (عاصمة فرنسا، 17×23، دالة بايثون) **خاطئة أو مبعثرة**: نموذج صغير ضعيف، غير صالح مساعدًا حتى الآن.
- **أخطاء وجدتُها وأصلحتُها (2026-11-08):**
  1. **المدرّب الحي على CPU كان ينهار** منذ تشغيل أدوات التدريب (7 نوفمبر): `sham_live` كان يضيف دفعة مبطّنة ثنائية الأبعاد كأنها مثال واحد فيسقط في `pad_batch` (`expand(LongTensor[4, 172], size=[4])`، خروج 134). الآن `tool_examples` تعيد أمثلة مسطّحة، مع اختبار. **غير مؤكد حتى يمرّ تشغيل مجدول كامل** (راقب `sham-cpu-trainer.yml`).
