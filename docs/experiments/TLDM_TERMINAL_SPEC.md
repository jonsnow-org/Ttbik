# الطرفية في مشروع SHAM T-LDM: ما قالته التقارير كله، وما بُني منه (2026-11-17)

المصادر: التقرير العربي (docx) · التقرير الإنجليزي · كتاب المشروع · ورقة «للمهندس» · السكربت المرجعي `ai-system/tldm/sham_tldm_reference.py`.

## 1) فهمي لنظام عمل الطرفية
1. **الطرفية ليست العقل.** هي فم وأذن ويد. العقل ثلاثة: الأوزان، محرك الاستدلال، وحلقة الوكيل. الطرفية هي **جسد** النموذج وبيئة عمله.
2. **حلقة الوكيل:** اقرأ من الطرفية ← ولّد ← إن كان أمرًا نفّذه وأعد النتيجة إلى السجل وأكمل ← وإلا اطبع الرد. بدون هذه الحلقة تصبح الطرفية شاتًا فقط.
3. **النموذج عامل لا كاتب:** يكتب **سطر أمر واحد** (`python organize.py`) بدل 300 كلمة شرح. المقياس الحقيقي مهام/ث لا رموز/ث (التقرير: 0.54 ث مقابل 33 ث، أي 61 ضعفًا).
4. **الجسد:** نظام الملفات = الذاكرة الطويلة (ما يتعلمه يُحفظ ملفًا أو محوّلًا أو ملاحظة)، وذاكرة العملية = القصيرة، والـshell = اليد.
5. **التطور الذاتي:** يولّد أمرًا ← تنفذه الطرفية فورًا وتعيد النتيجة (نجاح/فشل/خطأ/زمن) ← **النتيجة هي المكافأة** بلا إنسان ← النجاح يُحفظ محوّل LoRA، والفشل يُحفظ درسًا (`memory_lora/` و`memory_errors/`) ← `θ_new = θ_old + ΔLoRA`.
6. **بيانات التدريب:** كل مثال `{مهمة، أمر، نتيجة، نجاح}`، لا نص ميت فقط.
7. **الإدخال:** مستخدم، أوامر، ملفات، كود، سجلات، تُقرأ بالتوازي (قارئ خطي) وتُضغط إلى متجهات كامنة.
8. **الأمان (غير قابل للتفاوض):** sandbox دائمًا؛ قائمة ممنوعة (`rm -rf` و`sudo` و`passwd` و`shutdown` و`curl` و`wget`…) تُحجب؛ **تأكيد بشري** قبل `mkdir` و`pip` و`git` وكل أمر حساس؛ توقيع SHA256 لكل شريحة أوزان قادمة من الشبكة.
9. **محلي أولًا:** 80% من الطلبات يعالجها النموذج الصغير في طرفيتك، والشبكة للحالات الصعبة فقط، ويعمل بلا إنترنت.
10. **توجيه المالك:** الطرفية **مخفية**؛ المحادثة هي الواجهة وتوجّه الكلام إلى الطرفية، والمستخدم يرى الرد النهائي.

## 2) ما بُني منها وحالته

| البند | الحالة | أين / كيف يُختبر |
|---|---|---|
| طرفية معزولة، قائمة سماح، حجب الممنوع، حصر المسارات، بلا shell | **مبني ومختبر** | `ai-system/terminal/sandbox_terminal.py`، `test_all.py` |
| تأكيد بشري (`mkdir` وغيره)، و`pip`/`git` ممنوعان كليًا (أشد من الورقة) | **مبني ومختبر** | نفسه |
| سكربت موثوق بتحقق SHA256 (`organize.py`) | **مبني ومختبر** | `trusted` في الطرفية |
| سجل `{task, command, result, success, secs}` | **مبني** | الطرفية |
| أمر واحد من مهمة (مرة واحدة) ← تنفيذ ← حفظ نجاح/فشل | **مبني** (تجربة حاسمة قيد التدريب) | `terminal/terminal_loop.py` |
| حلقة متعددة الخطوات تعود فيها النتيجة إلى النموذج ويكمل | **جزئي**: كُتبت للمحادثة (`chat_to_terminal.py`) لكنها غير موصولة بـT-LDM، والنموذج لم يُدرَّب على مسارات متعددة الخطوات | يلزم بيانات مسارات |
| ذاكرة الملفات الطويلة تُقرأ في الخطوات التالية | **ناقص**: تُحفظ السجلات ولا تُقرأ | يلزم استرجاع |
| محوّل LoRA من النجاحات (التطور الذاتي الفعلي) | **ناقص**: نحفظ JSON فقط | يلزم تدريب محوّل على سجلات النجاح وقياس أثره |
| الطرفية المخفية خلف المحادثة (القرار: رد أم أمر) | **ناقص**: لا بيانات رد/أمر مختلطة | يلزم نوعا مثال |
| قياس مهام/ث ونسبة نجاح الأوامر وزمن الأسئلة البسيطة والصعبة | **جزئي**: `benchmark.py` يقيس رموز/ث فقط | يلزم قياس المهمة كاملة |
| محلي أولًا بلا إنترنت | يعمل محليًا على المعالج؛ تجربة الهاتف لم تُجرَ | لاحقًا |
| توقيع شرائح الشبكة، شبكة الطرفيات | **غير مبني** (يأتي مع الشبكة) | لاحقًا |

## 3) الترتيب الذي أكمل به
1. مسارات متعددة الخطوات تعود فيها النتيجة إلى المدخل، وبيانات «رد أم أمر».
2. ذاكرة الملفات: قراءة النجاحات السابقة والدروس.
3. محوّل LoRA من سجل النجاحات، ويقاس تحسّنه على مهام لم تنجح من قبل.
4. قياس المهمة كاملة (مهام/ث) مقابل نموذج يشرح بنص طويل.
5. بعد ذلك فقط: التحويل على نسخة من شام 2.
