# الاستضافة: الانتقال من Vercel Hobby إلى Oracle خلف بوابة Cloudflare (2026-10-18)

> **الحالة (2026-10-18):** نُفّذ النقل. البوابة `ttbik-gate.jonsnowx1r.workers.dev` تخدم من Oracle (الأساسي) وVercel احتياطي؛ الويبهوكات الـ13 على البوابة؛ `site.json` يضبط الهوية؛ المهام المجدولة تعمل من GitHub (`CRONS_ON`) وأُزيلت من `vercel.json`. التحويل بين الخوادم من لوحة «🌐 الاستضافة» في بوت أثر. نشر البوابة يتم من مشروع Cloudflare Workers Builds `ttbik-gate` (Root directory `cloudflare/site-gate`).

## 1) لماذا ننتقل
صفحة الاستخدام العادل في فيرسيل ([Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines)، محدّثة 2026-09-14): خطة Hobby «للاستخدام الشخصي غير التجاري فقط»، والتجاري يشمل معالجة دفعات الزوار وتضمين الإعلانات والإعلان عن بيع خدمة (التبرعات ليست تجارية). عندنا إعلانات ودفعات وترقيات. وتعليق المشروع يوقف **كل ويبهوكات البوتات** دفعة واحدة. فتصميم النقل هدفه: أن لا يكون في فيرسيل شيء حرِج، وأن يكون الرجوع إليه ضغطة زر.

## 3) البنية
```
تيليجرام / المتصفح / التطبيقات المصغرة / مهام GitHub المجدولة
                      │
          https://ttbik-gate.jonsnowx1r.workers.dev     ← عنوان واحد دائم (Cloudflare Worker: cloudflare/site-gate)
                 │ تلقائي: Oracle أولاً، وVercel إن لم يرد Oracle
        ┌────────┴─────────┐
   Oracle (الأساسي)     Vercel (الاحتياطي)
   Caddy → حاوية site    ttbik.vercel.app
        └────────┬─────────┘
       قاعدة البيانات نفسها (DATABASE_URL)
```
- كل شيء يشير إلى عنوان البوابة، فتبديل الخادم **لا يعني إعادة تسجيل ويبهوكات**.
- **لا أسرار في Cloudflare.** البوابة لا تحمل مفتاحاً ولا توكن بوت. أمر التحويل يصدر من **بوت أثر (لوحة المالك)** فينشئ في قاعدتنا رمزاً لمرة واحدة عمره دقيقتان، ثم يطلب من البوابة تطبيقه، فتسأل البوابة الخادمين (`/api/ops/gate-verify`) هل الرمز صحيح وماذا يسمح به، فيُستهلك. لا أحد غيرنا يستطيع إنشاء رمز.
- **تحويل تلقائي** حين يفشل Oracle (انقطاع الاتصال أو 502/503/504). خطأ تطبيقي 500 لا يُعاد إرساله، والكتابة التي انتهت مهلتها لا تُكرَّر. عند الفشل ترسل البوابة للخادم الاحتياطي ترويسة `x-gate-failover` فيرسل هو تنبيهاً إلى مالك بوت أثر (مرة كل 15 دقيقة).
- التثبيت على خادم («Oracle فقط» أو «Vercel فقط») يعود إلى «تلقائي» بعد 12 ساعة وحده.
- البث الصوتي والمرئي لا يمر بالبوابة (تحويل 307 إلى الخادم النشط)؛ ملفات `/_next/static` تُخزَّن على حافة Cloudflare.
- **هوية الموقع في ملف واحد:** `deploy/hosting/site.json` (`engineUrl` و`canonicalUrl`). يقرؤه بناء Vercel وبناء Oracle ومهام GitHub، فالخادمان متطابقان دائماً، والانتقال إيداع وليس تعديل لوحة. فارغ = لا تغيير.

## 3-ب) لوحة «🌐 الاستضافة» في بوت أثر (لوحة المالك)
تظهر في قائمة الأدمن (أو `/hosting`). تعرض حالة البوابة والوضع وصحة Oracle وVercel، وأزرارها: **تلقائي / Oracle فقط / Vercel فقط** · **نقل الويبهوكات إلى البوابة** (عرض ثم تنفيذ بزر ثانٍ) · **نقل الإعدادات إلى Oracle** (نافذة 15 دقيقة، مرة واحدة) · **تحديث الحالة**.

## 4) ما ينتقل وما يبقى (نقطة تحتاج قرارك لاحقاً)
- **ينتقل الآن:** البوتات (الويبهوكات)، التطبيقات المصغرة (التعارف، الوسائط، زنوبيا، أثر)، واجهات الدفع، المنصة، المهام المجدولة.
- **الموقع العام (المقالات والأدوات والإعلانات) مرتبط بعنوانه** `ttbik.vercel.app` (محركات البحث، ومفاتيح Adsterra/Monetag). لن يتغير شيء فيه تلقائياً: متغير جديد `NEXT_PUBLIC_CANONICAL_URL=https://ttbik.vercel.app` يُبقي الروابط القانونية وخرائط الموقع كما هي حتى بعد أن يصبح `NEXT_PUBLIC_SITE_URL` عنوان البوابة. أي أنه **يبقى على فيرسيل ويبقى فيه خطر المخالفة** (لكنه لم يعد يحمل البوتات). نقله يعني تغيير عنوانه وإعادة بناء ترتيب البحث واعتماد الإعلانات من جديد: قرار منفصل بعد أن يستقر نقل المحرك.
- **الإعلانات داخل التطبيقات المصغرة:** أضِف عنوان البوابة موقعاً جديداً في لوحتي Adsterra وMonetag (مجاناً) وإلا قد لا تعرض إعلاناً.

## 5) حدود يجب مراقبتها
- **سقف 100 ألف طلب يومياً** لحساب Cloudflare المجاني (الصفحة + الملفات + الويبهوكات كلها طلبات). الملفات الثابتة يخزنها المتصفح مدة طويلة فلا تتكرر لنفس المستخدم. راقب «Workers & Pages → ttbik-gate → Metrics»: إن تجاوزت 70 ألفاً يومياً فالحل المجاني الوحيد تقليل الطلبات (نقل ملفات ثابتة إلى `media-stream`-نمط، أو تحويل مسارات ثقيلة) وهو عمل أنجزه عندئذ. عند تجاوز السقف يردّ Cloudflare بخطأ 1027 (والرجوع الفوري: ضع الويبهوكات على أحد العنوانين المباشرين بأداة `rewebhook`، القسم 7).
- ذاكرة Oracle: 12GB، منها محرك الوسائط (حتى 4GB) وأثر ومشغّل شام والموقع (حتى 4GB). قِس بـ `free -h` بعد تشغيل الموقع.

## 6) خطوات النقل (آلية، وضغطتان منك في اللوحة فقط)
**ما أنجزته بنفسي:** البوابة وإنشاء مساحة KV (`ttbik-gate`) وربطها في `wrangler.jsonc`؛ اللوحة؛ `/api/health`؛ نقل الإعدادات؛ تشغيل الموقع على Oracle بعلم `agent/SITE_ON`؛ المهام المجدولة على GitHub؛ ودمج الفرعين وتوحيدهما. نُشر كل ذلك وهو يعمل على Vercel الآن (تحققت: `/api/health?deep=1` يعيد `db:true`، و`env-sync` يردّ 403 خارج النافذة).

**ما لم أستطع تنفيذه (حدّ صلاحياتي):** نشر البوابة نفسها على Cloudflare. لا أملك رمز نشر؛ جرّبت أن يُنشر مع تشغيل Workers Builds الخاص بـ`athar-meta` (خطوة `cloudflare/site-gate/deploy.sh` غير الحرجة التي تترك سجلاً في D1 باسم `ttbik-diag`) فلم يظهر Worker جديد. الحل بنموذج واحد في Cloudflare (كما نُشر `athar-meta`): Workers & Pages ← Create ← **Import a repository** ← `Ttbik` ← اسم المشروع `ttbik-gate`، **Root directory** = `cloudflare/site-gate`، الفرع `main`، أمر النشر الافتراضي `npx wrangler deploy` ← Save and Deploy. يقرأ `wrangler.jsonc` فيربط KV والمتغيرات وحده ويتحدّث عند كل دمج، ولا أسرار. بعدها يمكن حذف الخطوة غير الحرجة من `cloudflare/athar-front/wrangler.jsonc`.

## 7) الرجوع والطوارئ
- **تحذير من Oracle أو عطل:** اللوحة ← «☁️ Vercel فقط». (ثوانٍ.) وإن كان Oracle ساقطاً فالبوابة تحوّل وحدها وتنبّهك.
- **تحذير من فيرسيل:** اللوحة ← «🖥 Oracle فقط»، ثم أوقف النشر هناك. (لاحظ: إن كانت الويبهوكات على البوابة وOracle هو المخدِّم، فاللوحة نفسها تعمل منه.)
- **البوابة نفسها لا تردّ أو تجاوزت السقف:** من داخل خادم يعمل `POST /api/admin/hosting/rewebhook` بـ`base` = `https://ttbik.vercel.app` (أو `https://89-168-89-15.sslip.io`) يعيد كل البوتات إلى عنوان مباشر خلال دقيقة، ثم `engineUrl` فارغ في `site.json`.
- **الرجوع الكامل:** `rewebhook` إلى فيرسيل، `engineUrl` و`canonicalUrl` فارغان، احذف `CRONS_ON` وأعد `"crons"` إلى `vercel.json`، واحذف `SITE_ON`.

## 9) One line of history (2026-10-24, owner's order: Oracle is primary, everything else is backup)
Oracle builds `main`; Vercel builds the default branch `claude/free-services-marketplace-h6rwk2`. They had drifted (the same coder work landed on both as different commits, and Oracle served a build without the 10-23 terminal/stream routes). They were merged into one history on 2026-10-24 (both point at the same commit).
Rule from now on: **land every change on `main` first** (that is what the primary serves), then move the default branch to the same commit (`git push origin main:claude/free-services-marketplace-h6rwk2`, fast-forward only) so the Vercel backup is never behind. Never commit to only one of them. Check: `curl -s -o /dev/null -w '%{http_code}' https://<gate>/api/coder/terminal` must answer 401 on both Oracle and Vercel (404 = that server is on an old build).
