# Owner spec, 2026-09-12 (hf_video.py — real free ZeroGPU video path):
# the official client for calling a Gradio Space's own API
# programmatically (Client(space_id, hf_token=...).predict(...)) — the
# same library HF's own docs use for this, not a hand-rolled HTTP call.
#
# Real deploy failure on Render, 2026-09-12 (confirmed live in this
# service's own logs, then reproduced locally to find the exact cause):
# gradio_client==1.4.0 hard-pins "websockets<13.0,>=10.0" — but
# supabase==2.31.0's own realtime sub-dependency imports
# websockets.asyncio.client, a submodule that only exists in
# websockets>=13. pip silently resolved websockets down to 12.0 to
# satisfy gradio_client's cap instead of erroring, so the real break
# only surfaced at import time: "ModuleNotFoundError: No module named
# 'websockets.asyncio'" (app/quota.py -> app/supabase_client.py ->
# supabase -> realtime). gradio_client==2.7.0 drops that hard cap
# entirely (confirmed: its own METADATA has no websockets pin at all) —
# verified locally, a clean venv with this exact version list imports
# both supabase and gradio_client together with no conflict.
gradio_client==2.7.0

# Owner spec, 2026-09-13 (voice replies — app/tts.py): needed ONLY for
# Arabic, and only because the TTS model this project already pays
# nothing for cannot speak it. MeloTTS (CLOUDFLARE_TTS_MODEL) supports
# exactly six languages per its own docs — English, Spanish, French,
# Chinese, Japanese, Korean — and Arabic is not among them, so the
# owner's own language had no voice at all without this.
#
# Owner report, 2026-09-13 (real evidence: a voice reply said "شاكرنن"
# instead of "شاكراً"): gTTS is Google Translate's simple TTS endpoint,
# never built for Arabic grammar — replaced as the FIRST attempt by
# edge-tts (below), a real, free, no-key wrapper around Microsoft
# Edge's own neural TTS. gTTS is kept, not deleted, as the real second
# attempt for exactly the same reason it was chosen originally: it is
# an unofficial endpoint (Google Translate's), plausibly blocked on
# Render's shared cloud IP exactly as ddgs already is, and edge-tts is
# its own kind of unofficial client with the identical risk. tts.py
# treats either failing as normal and falls back to a text-only reply,
# so that outcome costs nothing either way. Pulls only click + requests
# — verified in a clean venv that it coexists with
# supabase/gradio_client/chromadb, the conflict class that broke this
# service once already.
gTTS==2.5.4
