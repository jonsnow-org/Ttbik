# Nova AI

مساعد ذكاء اصطناعي نملكه بالكامل — نص وصور وفيديو، بتكلفة تشغيل $0،
ثلاث واجهات (تيليجرام + ويب + API خارجي) تتصل كلها بنفس الخادم الوحيد.

## البنية بإيجاز (محدَّثة 2026-09-08 — تعكس الوضع الحالي الفعلي)

```
مستخدم (تيليجرام / Streamlit / API خارجي)
        │
        ▼
  FastAPI (ai-system/app) ← "الدماغ" الوحيد، منطق واحد لا يتكرر
        │
        ├─ MoE Router (router.py) — يصنّف السؤال محلياً بلا تكلفة (CODE/GENERAL/LIVE_INFO)
        ├─ RAG (rag.py) — ذاكرة شخصية + بنك حلول مشترك + بنك معلومات دائم (Supabase) + تخزين دلالي حقيقي + بحث ويب حي (ddgs)
        ├─ مجلس النماذج (council.py) — نموذجنا الخاص المُدرَّب أولاً ودائماً (عبر ModelScope Studio)، وGroq احتياط طارئ فقط عند تعطّل نموذجنا
        ├─ ملفات (files.py) — استخراج نص من PDF/Word (pypdf + python-docx)
        └─ الحصص/الاشتراك (quota.py) — يقرأ/يكتب في نفس مشروع Supabase
        │
        ▼
  ModelScope Studio (ai-system/modelscope-studio/app.py) ← الصوت الأساسي الحقيقي
        نموذجنا نحن (Qwen2.5-VL-7B مُدرَّب) يعمل هنا عبر llama.cpp — استضافة مجانية
        2 vCPU/16GB بلا بطاقة رسومية، لا نستأجره من أي شركة، بل نُشغّل كودنا عليه.
```

**تصحيح مهم عن نسخة سابقة من هذا الملف:** كانت تصف Groq/Gemini كصوت
أساسي — هذا لم يعد صحيحاً. نموذجنا الخاص (المُدرَّب عبر Kaggle، والمُستضاف
على ModelScope) هو الصوت الافتراضي لكل سؤال، نصاً كان أو صورة. Groq
احتياط طارئ فقط لو تعطّل نموذجنا، وGemini احتياط الرؤية فقط. راجع
`ai-system/app/council.py`'s module docstring للتفاصيل الكاملة وسبب هذا
الترتيب.

**القنوات المدعومة:** نص، رسائل صوتية (تُفرَّغ عبر Whisper المجاني على
Groq)، صور (فهماً عبر نموذجنا، وتوليداً عبر أمر `/صورة`)، فيديو (توليداً
عبر أمر `/فيديو`)، وملفات PDF/Word.

## الخطوة 1: احصل على المفاتيح المجانية (من متصفح الهاتف)

| المفتاح | من أين | ماذا تفعل |
|---|---|---|
| `GROQ_API_KEY` | https://console.groq.com/keys | سجّل دخول، اضغط Create API Key |
| `GEMINI_API_KEY` | https://aistudio.google.com/apikey | سجّل بحساب Google، Create API key |
| `HF_TOKEN` | https://huggingface.co/settings/tokens | أنشئ حساباً، New token بصلاحية Write |
| `MODELSCOPE_API_TOKEN` | modelscope.cn → إعدادات الحساب → Access Tokens | أنشئ توكناً (صيغة "ms-xxxxx") |
| `TAVILY_API_KEY` | https://app.tavily.com/ | سجّل (بريد أو Google/GitHub، بلا بطاقة) — المفتاح يظهر مباشرة في اللوحة (يبدأ بـ"tvly-") — يصلح مشكلة البحث الحي المحظور على Render |

اترك `HF_SPECIALIST_MODEL_ID`، `HF_IMAGE_MODEL_ID`، `HF_VIDEO_MODEL_ID`،
و`MODELSCOPE_SPACE_URL` فارغة حتى تُشغّل الدفاتر/تنشئ الاستوديو في
الخطوات التالية — Groq وGemini وحدهما يكفيان لتشغيل نظام يجيب فوراً،
قبل أن يكون نموذجنا الخاص جاهزاً.

نفس مشروع Supabase الذي يستخدمه موقع سوق تولز أصلاً — افتح SQL Editor
فيه، وشغّل كل ملف من هذه **مرة واحدة فقط**، بالترتيب:
1. `prisma/migration_19_nova_ai.sql` — الجداول الأساسية (NovaUser،
   NovaUsageLog، NovaSubscription).
2. `prisma/migration_22_nova_feedback.sql` — عمود التقييم الصامت.
3. `prisma/migration_23_nova_knowledge_bank.sql` — بنك المعلومات الدائم
   (`NovaKnowledgeEntry`) الذي يستخدمه كل من رد نوفا الفوري وتدريبه
   الأسبوعي، ومهمة `nova-knowledge-feed` اليومية على Vercel.

## الخطوة 3: انشر خادم FastAPI مجاناً (Render.com)

من متصفح الهاتف:
1. أنشئ حساباً مجانياً على https://render.com (تسجيل مباشر بحساب
   GitHub — لا بطاقة ائتمان مطلوبة)
2. اضغط **New +** ثم **Web Service**
3. اربطه بمستودع GitHub هذا (`Ttbik`)، وحدد **Root Directory** =
   `ai-system`
4. **Runtime**: اختر **Docker** (سيكتشف `ai-system/Dockerfile` تلقائياً)
5. **Instance Type**: اختر **Free**
6. من قسم **Environment Variables** أضف **كل** مفتاح من
   `ai-system/.env.example` كمتغير منفصل (نفس الأسماء بالضبط) — راجع
   ذلك الملف فهو المرجع الوحيد المحدَّث لقائمة المفاتيح الكاملة.
7. اضغط **Create Web Service** — بعد اكتمال البناء، رابط الخادم يكون
   شيئاً مثل `https://nova-ai-backend.onrender.com`

**ملاحظة الخطة المجانية:** الخدمة "تنام" بعد 15 دقيقة خمول، وأول رسالة
بعد نومها تأخذ حوالي 30-50 ثانية للاستيقاظ (طبيعي على الخطة المجانية).

## الخطوة 4: نموذج النص/الرؤية — استوديو ModelScope + تدريب Kaggle

هذا هو الصوت الأساسي الفعلي لنوفا، ويحتاج إعدادين منفصلين يعملان معاً:

### أ) أنشئ استوديو ModelScope (مرة واحدة)

1. من متصفح الهاتف افتح modelscope.cn وسجّل دخول
2. أنشئ Studio جديداً (SDK: **gradio**)، باسم مثل
   `nova-inference-server`
3. من صفحة الاستوديو، فعّل **Deploy via Git** لتحصل على رابط git
   الخاص به (تحتاجه لسر `MODELSCOPE_TOKEN` أدناه)
4. من صفحة "API documentation" الخاصة بالاستوديو، انسخ رابط الـ API
   وضعه في `MODELSCOPE_SPACE_URL` على Render

### ب) فعّل النشر التلقائي (GitHub Actions، مُعَدّ مسبقاً في هذا المستودع)

أضف هذين السرّين في GitHub (إعدادات المستودع → Secrets and
variables → Actions):
- `MODELSCOPE_TOKEN` — توكن وصول من modelscope.cn (منفصل عن
  `MODELSCOPE_API_TOKEN` أعلاه — هذا خاص برفع الملفات عبر git، ذاك
  خاص باستدعاء الـ API وقت التشغيل)
- `KAGGLE_API_TOKEN` — توكن Kaggle الجديد بصيغة واحدة (وليس
  اسم مستخدم+مفتاح القديم)

بمجرد إضافتهما، أي تعديل مستقبلي على `ai-system/modelscope-studio/`
يُنشَر تلقائياً على الاستوديو، وأي تعديل على
`ai-system/colab/merge_and_finetune.ipynb` يُدفَع تلقائياً لـ Kaggle
**ويُشغّل تدريباً حقيقياً فوراً** (يستهلك من حصة GPU الأسبوعية
المجانية — كن واعياً لهذا قبل أي تعديل على ذلك الملف تحديداً).

### ج) الإعداد لمرة واحدة داخل الدفتر نفسه على Kaggle

1. استورد `ai-system/colab/merge_and_finetune.ipynb` عبر GitHub import
   في Kaggle، فعّل **GPU T4** وفعّل الإنترنت من Settings → Turn on
   internet.
2. أضف عبر **Add-ons → Secrets**: `HF_TOKEN`، `HF_USERNAME`،
   `SUPABASE_URL`، `SUPABASE_SERVICE_ROLE_KEY`، `MODELSCOPE_TOKEN`،
   `MODELSCOPE_USERNAME` (إلزامية)، و`GROQ_API_KEY`/`GEMINI_API_KEY`
   (اختيارية، للتقطير المعرفي وقت التدريب فقط). أضف أيضاً
   `NOVA_BOT_TOKEN` و`SUPER_ADMIN_TELEGRAM_ID` (owner spec 2026-09-12:
   التقرير الأسبوعي الحقيقي — الخلية الأخيرة في هذا الدفتر تُرسل لك
   عبر تيليجرام ماذا تعلّم نوفا هذا الأسبوع فعلياً وهل تدرّب بأوزان
   جديدة — نفس القيمتين المستخدمتين أصلاً على Render).
3. **لا تستخدم "Schedule this notebook" الخاصة بـKaggle** — جربناها
   فعلياً ورفضتها Kaggle نفسها برسالة "Scheduled notebooks cannot use
   GPU"، وهذا الدفتر يحتاج GPU إلزامياً (تدريب Unsloth LoRA على نموذج
   7B مستحيل بدون GPU). التشغيل الأسبوعي التلقائي معدّ مسبقاً بطريقة
   أخرى تعمل فعلياً: جدولة أسبوعية (كل جمعة) داخل GitHub Actions نفسه
   (`.github/workflows/deploy-kaggle-notebook.yml`) — لا شيء تفعله
   هنا، فقط تأكد من إضافة الأسرار في الخطوة السابقة والاحتفاظ بنسخة
   ناجحة واحدة على الأقل من الدفتر.

من هذه اللحظة: كل تشغيل (سواء بسبب تعديل الكود أو الجدولة الأسبوعية)
يجلب المحادثات الحقيقية وبنك المعرفة، يدرّب نموذجنا تراكمياً (فوق نتيجة
الأسبوع الماضي، لا من الصفر)، يحوّله إلى GGUF، يرفعه لمستودعنا على
ModelScope، **ويجبر استوديو ModelScope على إعادة التحميل تلقائياً** —
لا خطوة يدوية متبقية بعد أول إعداد.

**أول مرة فقط:** بعد أول تشغيل ناجح، ضع اسم مستودع GGUF (تطبعه آخر
خلية، مثل `<اسمك>/nova-vision-7b-gguf`) في `MODEL_ID` داخل
`ai-system/modelscope-studio/app.py`.

### د) التطوير الذاتي التلقائي — نوفا يبحث ويتعلّم بنفسه (owner spec 2026-09-12)

هذا يجعل بنك معرفة نوفا (`NovaKnowledgeEntry`، نفس الجدول الذي يتدرب
عليه هذا الدفتر أسبوعياً في الخلية 4ب أعلاه) ينمو تلقائياً — لا ينتظر
سؤال مستخدم حقيقي — عبر بحث حي مجدول يومياً، موزَّعاً على مجالات
حقيقية متعددة (صور/فيديو/صوت/بحث حي/برمجة/أمان/جودة المحادثة/معرفة
عامة — `knowledge_store.DOMAINS`) بدل التعمّق في مجال واحد فقط، مع
قاعدة أمان حقيقية (`ai-system/app/guardrails.py`) تمنع تخزين أي كلمة
مرور/مفتاح API/بيانات حساسة، **و"تفكير" حقيقي لا تخزين أعمى**: كل
معلومة جديدة تُقارَن بما هو مخزَّن مسبقاً لنفس السؤال (عبر
`ai-system/app/knowledge_store.py`) — إن كانت تصحّح معلومة قديمة خاطئة
يُستبدَل القديم بها مباشرة، لا يُضاف كنسخة مكررة.

1. في مستودع GitHub → **Settings → Secrets and variables → Actions**،
   أضف: `SUPABASE_URL`، `SUPABASE_SERVICE_ROLE_KEY`، `GROQ_API_KEY`
   (نفس القيم الثلاث المستخدمة في Render)، وأيضاً `NOVA_FASTAPI_URL`
   و`NOVA_INTERNAL_SECRET` (نفس القيمتين من Render، لاقتراحات التطوير
   الذاتي أدناه).
2. `.github/workflows/gather-knowledge.yml` (بحث معرفي عام يومي) و
   `.github/workflows/propose-self-improvement.yml` (اقتراح تطوير ذاتي
   أسبوعي) يعملان تلقائياً — لا إعداد إضافي بعد إضافة الأسرار أعلاه.
3. كمالك، يمكنك أن تأمر نوفا مباشرة داخل محادثة تيليجرام عادية:
   - **"اذهب وابحث عن كذا وتعلّمه الآن"** → بحث وتخزين معرفة فوري (نية
     LEARN، انظر `rag.py`'s `learn_now`).
   - **"ابحث عن طرق لتطوير قدراتك في كذا"** → بحث عن أداة/طريقة حقيقية
     لتطوير نوفا نفسه، ينتج تقريراً (ماذا وجد، لماذا مفيد، ما الأثر)
     **وينتظر قرارك** (نية IMPROVE، انظر `ai-system/app/self_improve.py`)
     — وافق بـ`/موافقة_تطوير <رقم>` أو ارفض بـ`/رفض_تطوير <رقم>`. لا
     يُنفَّذ أي تعديل كود إلا بعد موافقتك الصريحة.
4. التقرير الأسبوعي (الخلية 13 في `merge_and_finetune.ipynb`) يرسل لك
   تلقائياً عبر تيليجرام ملخصاً حقيقياً لما أُضيف هذا الأسبوع ومصدره.
5. **أحضرت كود تدريب حقيقي بنفسك وتريد نوفا يدرّب نفسه به فعلياً؟**
   أرسله في رسالة تيليجرام عادية داخل علامات ```‎ وقل مثلاً "أضف هذا
   الكود لدفتر تدريبك ليطوّر نفسه به". نوفا لا يُنفّذ أي كود أبداً بنفسه
   (لا صلاحية تنفيذ لديه إطلاقاً، بشكل دائم) — لكنه يستخرج كودك حرفياً
   (بلا أي إعادة صياغة)، يفحصه نحوياً فحصاً حقيقياً، ويُدرجه كخلية جديدة
   في `ai-system/colab/merge_and_finetune.ipynb` عبر Pull Request حقيقي
   **لا يُدمَج تلقائياً** (لأن دمجه يُشغّل تدريباً حقيقياً على معالج
   Kaggle الرسومي فوراً ويستهلك من حصتك الأسبوعية) — راجع الرابط، ثم
   قل "وافق على الاقتراح رقم كذا" لدمجه فعلياً وبدء التدريب، أو "ارفض"
   لإلغائه دون دمج (انظر `self_improve.propose_training_notebook_change`).
6. **التفكير العميق** (`ai-system/app/deep_think.py`) — يعمل تلقائياً بلا
   أي إعداد. السؤال الصعب فقط (تحليل/مقارنة/تصميم/خطأ برمجي) يمر بـ:
   خطة ← بحث حي فعلي ← مسودة ← نقد ذاتي ← الرد النهائي **من نموذجنا
   نحن دائماً**. الأسئلة العادية لا تمر به إطلاقاً. وأثر التفكير
   يُخزَّن كبيانات تدريب ليدخل في أوزان نوفا في التدريب التالي — وهذا
   **يتطلب `migration_27`** (عمود `domain`)، وبدونه تعمل الردود ولا
   يُخزَّن التعلّم.
7. **بناء موقع/تطبيق كامل** — قل مثلاً "اصنع لي صفحة هبوط لخدمة كذا".
   نوفا يخطّط الملفات، يكتب كل ملف على حدة، **يفحص كلاً منها نحوياً**،
   ويفتح Pull Request واحداً بها جميعاً (حتى 5 ملفات). لا يُدمج
   تلقائياً عمداً: افتح الـPR وسيعلّق Vercel برابط معاينة حي لترى
   النتيجة بعينك قبل الدمج. **ممنوع على نوفا كتابة أي ملف تحت
   `.github/workflows/`** لأنه كود يُنفَّذ فعلياً على خوادم GitHub.
8. **الردود الصوتية** — بلا أي إعداد وبلا أي أمر: أرسل رسالة صوتية،
   يردّ عليك صوتاً (مع النص). صراحةً: نموذج Cloudflare المجاني
   (MeloTTS) **لا يدعم العربية**، فالعربية تمر عبر gTTS وهي واجهة غير
   رسمية قد تُحجب على Render تماماً كما حدث مع DuckDuckGo — وحينها
   يصلك النص وحده بلا أي عطل.
9. **صور بجودة أعلى (اختياري)** — أنشئ Space ثانياً على Hugging Face
   (SDK: Gradio، Hardware: ZeroGPU)، ثم **وافق مرة واحدة على ترخيص**
   `huggingface.co/stabilityai/stable-diffusion-3.5-medium` بنفس
   الحساب، ثم ضع `HF_IMAGE_SPACE_ID` في Render وفي أسرار GitHub. بدون
   هذا لا يتغيّر شيء — تبقى الصور من Cloudflare كما هي.
10. **هل نفع تدريب هذا الأسبوع؟** الخليتان 6ب و7ب في دفتر التدريب
   تسألان النموذج 12 سؤالاً ثابتاً قبل التدريب وبعده، ويحكم Groq بين
   الإجابتين دون أن يعرف أيّهما الأحدث، ثم يصلك التقرير على تيليجرام.
   يحتاج `GROQ_API_KEY` في أسرار Kaggle (مضاف عندك أصلاً).
11. شغّل `prisma/migration_26_nova_self_improvement.sql` و
   `prisma/migration_27_nova_knowledge_domains.sql` مرة واحدة في
   Supabase (بالإضافة إلى migration_25 إن لم تُشغَّل سابقاً).

## الخطوة 4-ب (اختياري): توليد الصور والفيديو

دفتر منفصل تماماً، يُشغَّل **يدوياً مرة واحدة** فقط (وليس أسبوعياً —
نموذج جاهز مُدرَّب مسبقاً، لا يحتاج إعادة تدريب):
1. استورد `ai-system/colab/generate_image_model.ipynb` بنفس الطريقة،
   فعّل GPU T4.
2. الأسرار المشتركة (`HF_TOKEN`، `HF_USERNAME`) تُقرأ تلقائياً إن كانت
   مضافة من الدفتر الآخر على نفس حساب Kaggle.
3. شغّل الخلايا من الأعلى للأسفل يدوياً — تُنزّل نموذج Stable
   Diffusion للصور وCogVideoX-2B (أو البديل الأخف) للفيديو، وتتحقق من
   عملهما فعلياً بتوليد عيّنة حقيقية قبل الرفع.
4. ضع اسمي المستودعين الناتجين في `HF_IMAGE_MODEL_ID` و
   `HF_VIDEO_MODEL_ID` على Render.

**صدق حول الفيديو:** خدمة HF المجانية لم تُؤكَّد أنها تخدم نموذج فيديو
مخصَّص فعلياً (راجع تعليق `generate_video` في `council.py`) — إن ظهرت
رسالة "غير متاح حالياً" عند تجربة `/فيديو`، هذا هو السبب الأرجح، وليس
عطلاً في الإعداد.

## الخطوة 5: انشر واجهة Streamlit (اختياري، مجاني)

1. من متصفح الهاتف افتح https://share.streamlit.io وسجّل دخول بحساب
   GitHub
2. اضغط **Create app** ثم **From existing repo**
3. اختر مستودع `Ttbik`، الفرع الصحيح، و**Main file path** =
   `ai-system/streamlit_app.py`
4. من **Advanced settings → Secrets** أضف بصيغة TOML:
   ```
   NOVA_FASTAPI_URL = "https://nova-ai-backend.onrender.com"
   NOVA_INTERNAL_SECRET = "نفس القيمة الموجودة على Render"
   ```
5. اضغط **Deploy**

## الخطوة 6: فعّل بوت Nova على تيليجرام من سوق تولز

في متغيرات بيئة Vercel لمشروع Ttbik، أضف:
- `NOVA_BOT_CREATOR_PASSWORD` — كلمة سر من اختيارك، تُدخلها عند تفعيل
  البوت من صفحة `/bots`
- `NOVA_FASTAPI_URL` — رابط الخطوة 3
- `NOVA_INTERNAL_SECRET` — **نفس القيمة على خادم FastAPI**
- `NOVA_BOT_TOKEN` — نفس توكن نوفا بوت من BotFather (يحتاجه الخادم
  ليُسلّم الردود البطيئة مباشرة لتيليجرام دون انتظار)
- `SUPER_ADMIN_TELEGRAM_ID` — معرّفك الرقمي على تيليجرام، لإعفائك أنت
  من حدود الاستخدام اليومية على نوفا (نفس القيمة أيضاً على Render)

ثم من `/bots` على الموقع، اختر قالب "Nova AI"، أدخل التوكن وكلمة
السر — يعمل البوت فوراً.

## ملاحظة الاشتراكات

لا يوجد دفع تلقائي — طلب "ترقية" يُنشئ صفاً بحالة `PENDING_APPROVAL`
في جدول `NovaSubscription`، وتُفعّله أنت يدوياً من لوحة تحكم نوفا
(`/admin/nova` على الموقع، أو أمر `/طلبات_الاشتراك` داخل بوت نوفا نفسه
لو كنت الأدمن الأكبر) — نفس أسلوب هذا المشروع في كل مكان آخر.
