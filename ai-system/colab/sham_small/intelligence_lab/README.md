# Sham Intelligence Lab (SIL)

**الحالة: حزمة بحث وتجهيز مستقلة — غير متصلة بشام v1 أو بأي مسار إنتاج.**

تجهّز هذه الحزمة بيانات وتجارب تعليم مرحلية للنموذج الصغير. لا تستورد model.py أو train.py أو sham_live.py أو serve.py أو أي وحدة تشغيل لشام. لا تبدأ التدريب، ولا تعدّل الأوزان، ولا تنشر نقاط حفظ، ولا تستدعي API لمعلم أو خدمة خارجية، ولا تنفذ نشرًا.

## النطاق

- عقد بيانات موحد ومؤرخ لإعداد التقطير متعدد المراحل.
- إدخال سجلات المعلم مع سلسلة نسب ومراجعة وحجر صحي.
- مسائل حسابية واستدلالية قابلة للتحقق.
- تعليم الاستناد إلى الأدلة، مع مشتتات وحالات لا تتضمن الإجابة.
- أمثلة عدم اليقين والامتناع وقياس ECE وBrier.
- مزج البيانات الطبيعية والاصطناعية ومخرجات المعلم المقبولة مع إزالة التكرار وتقرير حسب المهمة.
- منهج صعوبة متدرج وفصل train/dev/test حسب مجموعة المصدر.
- بوابة عدم تراجع لمقارنة مرشح بقاعدة أساس.
- تصدير JSONL وتقارير بناء وتقييم.

## المتطلبات

- Python 3.10 أو أحدث.
- المكتبة القياسية فقط لإعداد البيانات والتقييم.
- لا يلزم PyTorch أو Transformers أو datasets أو أوزان نموذج أو مفاتيح API.

## التشغيل السريع

من جذر المستودع، نفّذ:

    PYTHONPATH=ai-system/colab/sham_small/intelligence_lab/src python -m sham_intelligence_lab.cli build --out /tmp/sham-intelligence-lab --count-per-task 100

لاستيراد سجلات طبيعية أو سجلات معلم اختيارية:

    PYTHONPATH=ai-system/colab/sham_small/intelligence_lab/src python -m sham_intelligence_lab.cli build --out /tmp/sil --count-per-task 100 --natural-jsonl /path/to/natural.jsonl --teacher-jsonl /path/to/teacher.jsonl

صيغة السجل موثقة في schema.py، ويوجد مثال في teacher_input.example.jsonl. كل سجل معلم يحتاج teacher_id. مخرجات المعلم تظل غير موثوقة وتُحجر ما لم يضع المراجع reviewed=true وverification_status=passed، ثم يعاد تشغيل المدقق المستقل.

تُشتق ملفات المنهج وملفات مراحل التقطير من TRAIN فقط. يجب عدم إدخال DEV أو TEST في التدريب أو توليد أمثلة المعلم أو إعداد البيانات أو ضبط المعاملات.

## خطة التعلم المرحلية

1. **تأسيس السلوك:** بيانات طبيعية ومظاهرات معلم تمت مراجعتها بعناية.
2. **الاستدلال القابل للتحقق:** مسائل حتمية لها إجابات رقمية أو منطقية يمكن التحقق منها.
3. **الارتكاز إلى الأدلة:** الإجابة من المقاطع المتاحة، وذكر المصدر، والامتناع عند الغياب أو التعارض.
4. **معايرة عدم اليقين:** تسميات الثقة وسلوك الامتناع وقياس ECE وBrier على مجموعة معايرة منفصلة.
5. **الإصلاح والنقل:** اكتشاف الإجابات الوسيطة الخاطئة وتصحيحها مع حماية اللغة العامة والمهارات السابقة.

نسبة 70/30 بين الطبيعي والاصطناعي نقطة بداية للتجربة فقط. لا يصطنع المازج بيانات لتعويض غياب مصدر. على المهندس اختبار 50/50 و70/30 و85/15 وتسجيل النتائج لكل مهمة.

## حدود التحقق

- التحقق الحسابي حتمي ويستخدم قواعد AST محدودة؛ لا يستخدم eval ولا يسمح باستدعاءات أو أسماء أو خصائص أو imports.
- تحقق evidence_substring لفظي فقط، وليس إثباتًا للاستلزام الدلالي. الادعاءات الدلالية تتطلب مراجعة مستقلة أو محكمًا.
- سجلات abstain_expected وlabelled_decision تتطلب مراجعة سياسة مخصصة.
- ثقة المعلم ليست دليل صحة. سجلات المعلم غير المراجعة تبقى في الحجر الصحي، وأي إخفاق في المدقق يرفض السجل.
- لا توجد آلية لتنفيذ كود مولد من النموذج. يجب التحقق من مهام البرمجة بخدمة اختبارات معزولة مستقلة يوافق عليها المهندس.

## بوابة القبول

تتطلب الإعدادات الافتراضية:
- ما لا يقل عن 100 مثال تقييم لكل مهمة مطلوبة.
- تحسنًا متوسطًا نسبيًا في الخسارة لا يقل عن 0.5%.
- ألا تتراجع خسارة أي مهمة مطلوبة بأكثر من 2%.
- ألا تنخفض الدقة بأكثر من نقطة مئوية واحدة.
- ECE لا يتجاوز 0.12.

هذه حدود هندسية أولية وليست ثوابت علمية. يجب تجميد مجموعة الاختبار وإصدارها قبل الاستخدام، والإبلاغ عن فواصل الثقة وثلاث بذور تدريب على الأقل قبل ترقية أي مرشح.
