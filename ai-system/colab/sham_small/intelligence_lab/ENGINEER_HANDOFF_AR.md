# ملاحظة تسليم للمهندس — Sham Intelligence Lab

## الحالة والحدود

هذه حزمة بحثية مستقلة أُنشئت على فرع منفصل. لا تربطها الآن بأي مسار فعلي في شام v1. لم تتغير ملفات model.py أو train.py أو sham_live.py أو serve.py أو نقاط الحفظ أو مهام التدريب. لا تستورد الحزمة أيًا من وحدات تشغيل شام.

**المطلوب منك أولًا المراجعة فقط، ثم تقديم خطة ربط منفصلة. لا تدمجها مع مسارات شام قبل موافقة مالكة المشروع.**

## مكونات الحزمة

- **schema.py:** عقد بيانات موحد بإصدار sil-1.0، يتضمن مصدر المثال ونوع المهمة والصعوبة والتحقق والأدلة وسلسلة النسب.
- **generators.py:** مولدات حسابية متعددة الصعوبة، وأمثلة استدلال منطقي، وأمثلة تعتمد على الأدلة مع حالات غياب الإجابة، وأمثلة عدم اليقين وإصلاح الأخطاء.
- **verifiers.py:** مدقق حسابي آمن محدود القواعد، ومدقق رقمي واختيار مغلق. لا ينفذ eval ولا ينفذ كودًا مولدًا.
- **distillation.py:** استيراد سجلات المعلم وتوزيع البيانات على مراحل التقطير؛ مخرجات المعلم غير موثوقة افتراضيًا وتذهب إلى الحجر الصحي حتى مراجعتها المستقلة.
- **mixture.py:** إزالة التكرار ومزج الطبيعي والاصطناعي والمعلم مع تقرير لكل مهمة.
- **curriculum.py:** منهج من ثلاث مراحل للصعوبة، ولا تتم الترقية إلا بعد بلوغ الإتقان في كل المهام الفعالة.
- **splits.py:** فصل حسب مجموعة المصدر لمنع انتقال أمثلة المصدر الواحد بين التدريب والتقييم.
- **uncertainty.py:** قياس ECE وBrier وتحديد قرار الإجابة أو الاسترجاع/الامتناع.
- **gates.py:** بوابة عدم تراجع متعددة المهام.
- **eval_harness.py:** تقييم التنبؤات المحفوظة من دون تحميل نموذج، وتلخيص الدقة والتغطية والامتناع والخسارة والمعايرة.
- **pipeline.py وcli.py:** بناء ملفات JSONL وتقارير التجهيز دون تحميل نموذج أو تدريب.

## مراجعات إلزامية قبل الربط

1. مراجعة منطق كل مولد، والتحقق من الحلول المتوقعة يدويًا وعلى اختبارات مستقلة.
2. تدقيق التراخيص ومصدر كل مجموعة طبيعية أو اصطناعية قبل اعتمادها تجاريًا.
3. مراجعة منع تسرب المجموعات. يجب أن تكون مجموعات DEV/TEST ثابتة ومجمدة ولا تدخل في تدريب المعلم أو توليد الأمثلة أو ضبط المعاملات.
4. مراجعة جودة أمثلة المعلم: لا تعتمد على تقييم المعلم لنفسه، واستخدم تحققًا مستقلًا أو محكمين.
5. إضافة تحقق دلالي للأدلة؛ فمدقق substring المرفق ليس كافيًا لإثبات الاستلزام.
6. تحديد بروتوكول مهام البرمجة داخل Sandbox خارجي معزول. لا تشغّل كود النموذج على بيئة المضيف.
7. تحديد صيغة تحويل Example إلى تنسيق المحادثة الذي يستخدمه شام، مع الحفاظ على أقنعة prompt والأدلة وأدوار المعلم والمساعد.
8. تحديد هل تُستخدم شروح الحلول المختصرة كأهداف تدريبية، وكيف يتم منع تعلم نصوص تفسيرية زائدة أو خاطئة.
9. تنفيذ تجارب نسب المزج ومراحل المنهج على نسخة تجريبية غير إنتاجية، بثلاثة بذور تدريب على الأقل.
10. تشغيل اختبارات عدم التراجع على مجموعة مجمدة تشمل العربية العامة والمحادثة والمعرفة والاستدلال والأدلة وعدم اليقين والبرمجة عند توفرها.

## خطة ربط مقترحة بعد المراجعة

- أضف Adapter مستقلًا في طبقة تجهيز بيانات التدريب، ولا تعدل النواة أو الاستدلال.
- ابدأ بتصدير train.jsonl فقط إلى Dataset تجريبي منفصل.
- أبقِ dev.jsonl وtest.jsonl خارج كل مسارات التدريب.
- أنشئ Checkpoint تجريبيًا باسم منفصل، ولا تستبدل نقطة شام الرئيسية.
- شغّل بوابة المقارنة، وسجّل baseline/candidate ومجموعة البيانات وبصمة الإعدادات والـ seed.
- لا تعتمد أي نموذج إذا تراجع أداء أي مهمة أساسية فوق حدود السياسة أو فشل معايرة عدم اليقين.

## أمور لم تُنفذ عمدًا

- لم يتم استدعاء أي API لمعلم أو مزود بيانات.
- لم يتم تعديل Tokenizer شام أو أوزانه.
- لم يتم تشغيل تدريب أو QAT أو ضغط أو نشر.
- لم يتم ربط البيانات بمجلدات أو دفاتر التدريب القائمة.
- لم تتم إضافة قواعد إجابات جاهزة إلى استدلال النموذج.
- لم يتم استيراد أو تعديل أي ملف من مسارات تشغيل شام داخل هذه الحزمة.

## المطلوب في رد المراجعة

قدّم جدولًا يذكر: الملفات المقبولة، الملفات التي تحتاج تعديلًا، المخاطر، تحويل تنسيق البيانات إلى شام، الاختبارات المطلوبة، وأثر الموارد على CPU وRAM. لا تبدأ الربط قبل اعتماد المراجعة.
