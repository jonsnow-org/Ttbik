# Muse Spark Open على جيتهوب + تليجرام

نظام صغير: تكتب في تليجرام ← تُفتح قضية (Issue) في جيتهوب ← **Muse Spark Open** يردّ عليها (وفي الوضع الكامل يفتح طلب دمج) ← يصلك الرد في تليجرام.

## عن النموذج (تحقّقتُ منه على هوكينك)
- المعرّف الصحيح: **`meta-models/Muse-Spark-Open-816B-A42B`** (المعرّف `meta-muse/Muse-Spark-Open` الذي ذُكر لي غير موجود).
- نموذج من ميتا، **مغلق خلف موافقة (gated)**، رخصة `other`، متعدد الوسائط (نص + صور)، معماريته خليط خبراء: **816 مليار معامل، 42 مليارًا فعّالة لكل رمز**.
- يُستدعى هنا عبر **Hugging Face Inference Providers** (المزوّد الحي وقت الكتابة: Baseten) باستخدام `HF_TOKEN`، دون `dev.meta.ai`.
- **التكلفة:** هذا مزوّد مدفوع بالاستهلاك يُحاسَب من رصيد هوكينك؛ الرصيد المجاني الشهري صغير. إن نفد يكتب Muse في القضية أن الرصيد انتهى ولا يفشل بصمت. غيّر النموذج بمتغير المستودع `MUSE_MODEL` إن أردت نموذجًا أرخص.

## الملفات
| الملف | وظيفته |
|---|---|
| `.github/workflows/muse-spark-open.yml` | يعمل عند فتح قضية أو إضافة وسم أو تعليق `/muse` |
| `.github/workflows/telegram-bridge.yml` | كل 5 دقائق يلتقط رسائل تليجرام ويفتح قضايا، ويرسل ردّ Muse إلى تليجرام |
| `muse-spark/muse_agent.py` | المحرّك: يقرأ القضية، يستدعي النموذج، يكتب التعليق أو يفتح طلب الدمج |

| `muse-spark/test_muse.py` | اختبارات بلا شبكة: `python -m unittest muse-spark/test_muse.py` |

## الوضعان
- **عادي (بلا وسم):** تعليق وتحليل فقط. لا يغيّر شيئًا في المستودع.
- **كامل (وسم `muse-full`):** ينشئ فرعًا جديدًا `muse/issue-<رقم>-<وقت>`، يعمل commit، يدفع **الفرع**، ويفتح طلب دمج.
- **`main` لا يُكتب عليه أبدًا:** الكود نفسه يرفض أي كتابة على الفرع الافتراضي (ليس وعدًا للنموذج). وأوصيك بتفعيل حماية الفرع أيضًا (انظر الخطوة 5).

## قواعد الأمان المطبّقة في الكود
- لا يعالج إلا قضية **موثوقة**: كاتبها المالك/عضو/متعاون، أو عليها وسم `from-telegram` (لا يضيف وسمًا إلا من يملك صلاحية كتابة، والجسر لا يقبل إلا رسائل محادثتك).
- النموذج **لا ينفّذ أوامر**: يعيد JSON فقط، والسكربت يتحقق ويكتب الملفات بنفسه.
- مسارات محظورة: `athar/` و`cloudflare/` و`deploy/oracle/` و`.github/workflows/` وملفات الأسرار وملفات التعليمات (`CLAUDE.md`…) وأي هروب من المسار؛ 12 ملفًا كحد أقصى.
- لا تُعالَج القضية نفسها مرتين (ذاكرة `actions/cache@v4` في `muse-cache.json`؛ المفتاح يتغير عند تغيّر النص أو الوضع).
- لا يُطبع أي سر في السجلات.

## الإعداد خطوة بخطوة
### 1) أنشئ بوت تليجرام
1. افتح تليجرام وابحث عن **@BotFather**.
2. أرسل `/newbot` ← اختر اسمًا (مثل: Muse Spark) ← اختر معرّفًا ينتهي بـ `bot`.
3. سيعطيك **توكن** يشبه `123456789:AA...` — هذا هو `TELEGRAM_BOT_TOKEN`. لا تشاركه مع أحد.
4. افتح بوتك وأرسل له أي رسالة، ثم افتح في المتصفح: `https://api.telegram.org/bot<التوكن>/getUpdates` وابحث عن `"chat":{"id":123456789` — هذا الرقم هو `TELEGRAM_CHAT_ID` (محادثتك أنت؛ البوت يتجاهل كل من سواك).

### 2) أنشئ توكن هوكينك
هوكينك ← Settings ← Access Tokens ← New token (نوع **Read** يكفي لاستدعاء Inference Providers) — هذا هو `HF_TOKEN`. فعّل «Make calls to Inference Providers». اقبل شروط النموذج في صفحته إن طلب ذلك.

### 3) أضف الأسرار في جيتهوب
المستودع ← Settings ← Secrets and variables ← Actions ← **New repository secret**، وأضف الثلاثة: `HF_TOKEN` و`TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID`.
(اختياري، في تبويب Variables: `MUSE_MODEL` لتغيير النموذج، و`MUSE_PAUSE=1` لإيقاف النظام كله فورًا.)

### 4) اسمح لجيتهوب بفتح طلبات الدمج
Settings ← Actions ← General ← Workflow permissions ← **Read and write permissions** + فعّل **Allow GitHub Actions to create and approve pull requests**.

### 5) احمِ `main` (موصى به)
Settings ← Branches ← Add branch ruleset ← الفرع `main` ← **Require a pull request before merging**. هكذا يُمنع أي push مباشر حتى من غير هذا النظام.

### 6) جرّب
أرسل لبوتك: `/build صفحة login` ← ستصلك رسالة «استلمتُ طلبك — القضية #N»، ثم الرد بعد دقائق.
يدويًا بلا تليجرام: افتح قضية بوسم `from-telegram`، أو شغّل Muse Spark Open من تبويب Actions برقم القضية.

## الربط ببوت نوفا (مسار منفصل عن كل النماذج)
بدل بوت مستقل يمكنك الكلام مع Muse من بوت نوفا نفسه. الكود في `src/lib/museBridge.ts` ويُستدعى **قبل** أي نموذج (نوفا وشام وشام v2 والمرشحين)؛ لا يمرّ بأي نموذج ولا يغيّر محادثتك معهم:
1. أنشئ في جيتهوب توكنًا دقيق الصلاحيات (Settings ← Developer settings ← Fine-grained tokens): المستودع نفسه فقط، صلاحية **Issues: Read and write**.
2. في إعدادات الاستضافة (Vercel) أضف المتغيرين: `MUSE_GITHUB_TOKEN` (التوكن) و`MUSE_REPO` (مثل `jonsnow-org/Ttbik`).
3. في أسرار جيتهوب اجعل `TELEGRAM_BOT_TOKEN` هو **توكن بوت نوفا** و`TELEGRAM_CHAT_ID` معرّف محادثتك، وفي Variables أضف `MUSE_POLL=0` (بوت له webhook لا يجوز أن تستمع إليه مهمة أخرى في الوقت نفسه).
4. اكتب في بوت نوفا: `/build ...` أو `/fix ...` أو `/muse ...` أو `/full ...` — للمالك فقط. يردّ البوت «استلمتُ طلبك — القضية #N»، ثم يصلك ردّ Muse في المحادثة نفسها.

## أوامر تليجرام
| الأمر | الأثر |
|---|---|
| `/build <نص>` | قضية «Telegram: [نص]» — وضع عادي |
| `/fix <نص>` | مثله |
| `/full <نص>` | يضيف الوسم `muse-full` — فرع + commit + طلب دمج (لا يمس `main`) |
| أي نص آخر | وضع عادي |

## حدود يجب أن تعرفها
- جيتهوب لا يستقبل webhook من تليجرام، لذا المهمة تستمع كل 5 دقائق (long polling): قد يتأخر الرد حتى 5 دقائق. لبوت فوري شغّل `python muse-spark/telegram_bot.py` على أي جهاز يبقى مفتوحًا (بالتوكنات نفسها كمتغيرات بيئة).
- كل مهمة استماع تستهلك دقائق Actions؛ المستودع العام بلا حدّ، أما الخاص فحدّه الشهري محدود. أوقفها بـ `MUSE_PAUSE=1`.
- طلبات الدمج التي ينشئها `GITHUB_TOKEN` لا تُشغّل فحوص CI تلقائيًا (قيد في جيتهوب)؛ راجعها واضغط «Re-run» أو أغلقها وأعد فتحها.
- نموذج بهذا الحجم قد يكتب كودًا خاطئًا؛ طلب الدمج هو نقطة المراجعة البشرية، لا تدمجه بلا قراءة.
