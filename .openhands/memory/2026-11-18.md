
## Nova reply-hygiene parity with Sham 2 (2026-11-18)
Ported Sham 2's model-agnostic reply hygiene to Nova as its OWN module to keep the models independent:
`src/lib/novaReplyGuard.ts` (`visibleNovaReply(text, prior)` -> `{ text, blocked }`; collapses adjacent duplicate
sentence blocks 1-6, replaces an echoed/raw-dump reply with an honest line in the text's language). Wired into the
user-facing final-answer path in `coderSections.ts` `driveLoop` (~line 2521), guarded by `!calls.length && !run.agent`
(user-facing only, not sub-agent reports) and offset-safe (skip rewrite if `max(botSent,sent,logged)` already showed
text; on block, reset those offsets so the honest line is delivered). Kill switch `CODER_REPLY_GUARD=off`.
Tests: `novaReplyGuard.test.ts` (11) + `novaReplyGuardFlow.test.ts` (2, through the real loop). tsc clean.
NOT ported (Sham-2 specific, `modelId === "sham_v2"` gated): T-LDM route, desktop 412 retry.

## Nova 1 / Nova 2 T-LDM session
- Analysed Sham 2's T-LDM (`sham_tldm_serve.py`, `train_sham2.py`, `sham2.yaml`, `tldmPolicy`, `shamStudio.shamGenerateTldm`)
  and transferred the *technique* only, per model.
- Key discovery: `novaModelOf()` maps Sham ids to `undefined`, so `isTldmModel(novaModelOf(st.model))` is the clean way to
  ask "is the chat's model one of Nova's own".
- Two design traps handled: (1) `CoderOutcome.failure` has a closed union, so a T-LDM error must be returned as
  `{ reply }` with NO `failure` — otherwise the outage-retry loop retries for minutes and then reports a generic
  "server unreachable"; (2) `taskEvent` kinds have no `"error"` — use `"failed"`.
