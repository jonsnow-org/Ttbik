## Second pass — practical testing found two real bugs (commit 2f030fe, + touch fix)

The directive was to test practically, not just read code. Two real defects came out of running the
stream against the real SQL engine and reasoning about touch events:

1. **`mergeTaskEvents` crashed the chat on first paint.** `listTasks` returns task ROWS with no `events`
   field (only the `thread` op pairs a row with its events). The SSE stream can deliver the first `text`
   event before the thread op has paired them, so `task.events.map(...)` threw `Cannot read properties of
   undefined`. Guarded with `task.events || []`; `lastEventId` guarded too. Covered by
   `liveEvents.test.ts` ("starts a run whose row carries no events yet").
2. **A tap on the desktop clicked twice.** `onTouchStart` fires, then the browser synthesises a `click`;
   both called `clickScreen`, so every touch reached the desktop as a double-click (folders opened, text
   selected). Added a 700 ms `touchAt` ref guard in `GraphicalDesktop.tsx`.

## Third pass — Sham v1 development (owner order: "develop old Sham; fix everything")

Ran EVERY `if __name__ == "__main__"` self-test in `ai-system/colab/sham_small` practically. Six real defects,
all fixed (commits 054478f, b3b3143):

1. **`sham_tools_data.py` TOOL_SPECS missing 10 tools.** The live engine `src/lib/shamExec.ts` offers
   `computer_run/write/read/job/edit/repo/search/publish`, `browser`, `desktop` — none existed in the
   training specs, so a trained Sham was never taught the very tools its engine gives it (the owner's
   "components not connected to their correct paths"). Added them + 12 catalog examples; the self-test
   compares `set(TOOL_SPECS)` to the `tool("…")` names parsed out of `shamExec.ts` and now passes.
2. **`FORMAT_LINE` drift.** Live `FORMAT_CODE` moved to the persistent computer (computer_write/edit/run/job);
   the training copy still said "sandbox_write_file ثم sandbox_exec". Resynced byte-for-byte (asserted).
3. **`qwen3_tool_examples` infinite loop.** `while len(out) < n:` had no progress guard, so a window too small
   for a case spun forever. Now shrinks the tool block and gives up after a bounded attempt count.
4. **`build_general_tokenizer.py` clobbered the live tokenizer.** A bare run wrote over the 32k
   `sham_general_tokenizer.json` (it did: 32000 → 2 entries during this session; restored from git). Now
   refuses unless `--force`, and honors `SHAM_TOKENIZER_OUT`.
5. **ffmpeg n9 removed `-vsync`.** `imageio-ffmpeg` ships ffmpeg n9.0.2; every `-vsync vfr` video frame
   extraction raised "Unrecognized option vsync" and each clip was silently counted as `dropped`
   (`sham_data_sources.py`, `data_acquisition.py`). Switched to `-fps_mode vfr`; video collection works again.
6. **`text_tokenizer.py` glob hit directories.** Next.js route dirs named like text files
   (`src/app/indexnow-key.txt/` …) were fed to the BPE trainer → "Is a directory (os error 21)". Filter to files.

`sham_gh_collect` "timeout" is NOT a bug: it is a 5.3-hour crawler by design.
